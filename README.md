# LiveChat

Онлайн-чат поддержки для нескольких сайтов: встраиваемый виджет, единая панель оператора, WebSocket, PostgreSQL и изоляция данных по сайтам.

## Текущий статус

Реализовано серверное ядро:

- PostgreSQL и SQL-миграции.
- Авторизация владельца-оператора по JWT.
- Несколько сайтов с отдельными настройками и публичными ключами.
- Посетители, диалоги, сообщения, статусы, внутренние заметки.
- WebSocket для сообщений, статусов, «печатает» и согласованного предпросмотра черновика.
- Редактирование сообщений оператора с внутренней историей изменений.
- Быстрые ответы оператора, общие и для отдельного сайта.
- Настройки сайта и три стартовые кнопки.
- Ограничение частоты запросов, валидация данных, изоляция сайтов.
- Docker Compose для локального запуска.

Ещё не реализовано:

- Визуальный виджет посетителя — Этап 2.
- Панель оператора — Этап 3.
- Загрузка изображений и файлов — Этап 4.
- Оценка диалога, рабочее время, автоприглашения, уведомления — Этап 4.

## Локальный запуск

```bash
cp .env.example .env
npm install
docker compose up -d db
npm run db:migrate
npm run dev:server
```

Сервер: http://localhost:3000

При первом запуске создаются владелец из `OWNER_EMAIL` и `OWNER_PASSWORD`, а также два демо-сайта. Их публичные ключи выводятся в лог сервера.

## Деплой на Railway

1. Подключите репозиторий GitHub к Railway.
2. Создайте сервис из репозитория: Railway обнаружит `Dockerfile`.
3. Добавьте PostgreSQL: Railway создаст переменную `DATABASE_URL`.
4. Добавьте переменные `JWT_SECRET`, `OWNER_EMAIL`, `OWNER_PASSWORD`, `PUBLIC_URL`.
5. Для файлов в будущем подключите Railway Volume и укажите путь в `UPLOAD_DIR`.

## Безопасность

- Секретные ключи не попадают в код виджета: виджет получает только публичный `siteKey`.
- CSS виджета будет изолирован через Shadow DOM.
- Черновик посетителя не сохраняется в базе, логах и истории.
- Город определяется приблизительно по IP только при подключённой базе MaxMind GeoLite2.
