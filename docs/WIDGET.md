# Виджет: этап 2а

Виджет на чистом JavaScript, без новой сборки и зависимостей. Изоляция CSS через Shadow DOM. Запуск из server/public/widget.js.

## Проверка локально

1. git pull
2. npm run dev:server
3. В отдельном терминале авторизуйтесь через POST /api/auth/login. Полученным Bearer-токеном вызовите GET /api/sites.
4. Сохраните publicKey первого сайта. Для локальной проверки измените его domain на localhost через PATCH /api/sites/:id. Второму сайту можно назначить 127.0.0.1.
5. Вставьте скрипт ниже в HTML-страницу, обслуживаемую по HTTP с разрешённого домена. Не открывайте страницу через file://.

```html
<script async src="http://localhost:3000/assets/widget.js" data-site-key="PUBLIC_KEY_1"></script>
```

Для второго сайта используйте его отдельный publicKey. В production замените localhost на HTTPS-домен сервера Railway, а разрешённые домены сайтов — на реальные.

## Реализовано

- Shadow DOM, светлая/системная тёмная тема, клавиатурный фокус, Escape, Enter/Shift+Enter.
- Приветствие и три кнопки, отправляющие выбранный текст.
- История с сервера, токен в localStorage отдельно для siteKey.
- Очередь неподтверждённых сообщений в localStorage и повтор с тем же clientId.
- Переподключение с задержкой, загрузка истории после переподключения.
- Отображение обновлённых ответов оператора и входящий индикатор печати.
- Счётчик сообщений, пришедших пока окно свёрнуто.

## Пока не готово — не публиковать на боевые сайты

Сервер требует усиления безопасности: точного сравнения Origin, проверки прав ack, ограничений размера WebSocket-пакета и обработки ошибок. Предпросмотр черновика намеренно не подключён в виджете до реализации серверной проверки отдельного согласия и очистки черновиков. Операторская панель, файлы, автоответы кнопок, отправка подтверждений доставки/прочтения, офлайн-форма, рейтинг, обновление текущей страницы, правила скрытия и расписание ещё не реализованы в интерфейсе. Соединение не равно присутствию оператора.

## Проверки

1. Отправить текст, обновить страницу: сообщение осталось.
2. Остановить сервер, отправить сообщение, запустить сервер: очередь отправлена, дубля в БД нет.
3. Свернуть окно, ответить через API оператора: появился счётчик.
4. Изменить ответ через API: текст обновился, появилась отметка «Изменено».
5. Вставить HTML в сообщение: отображается текст, а не разметка.
6. Проверить узкое окно, экранную клавиатуру на реальном телефоне и управление Tab/Escape.

Сборка и браузерные тесты в среде ассистента не запускались. Текущий Dockerfile ещё требует исправления перед Railway: ссылается на отсутствующие приложения apps/operator и apps/widget.
